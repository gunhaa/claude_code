# CLAUDE.md 효과적인 작성 팁

---

## Tip 1. 모호한 말 대신 실행 가능한 명령을 써라

Claude는 지침을 문자 그대로 해석합니다. 의도가 아닌 행동을 기술하세요.

```markdown
# 나쁜 예
- 테스트를 잘 실행해라
- 코드를 깔끔하게 유지해라

# 좋은 예
- 커밋 전 반드시 `npm test && npm run lint` 실행
- 함수 하나당 20줄 이하로 유지
```

---

## Tip 2. 금지 사항은 "하지 말 것"으로 명시해라

Claude는 긍정문보다 명시적 금지가 더 강하게 작동합니다.

```markdown
# 나쁜 예
- 가능하면 console.log는 피해라

# 좋은 예
- console.log를 프로덕션 코드에 절대 남기지 말 것
- --force 옵션을 git 명령에 사용하지 말 것
- 확인 없이 파일을 삭제하지 말 것
```

---

## Tip 3. 중요도를 단어로 구분해라

모든 지침이 같은 무게로 처리되면 정작 중요한 것이 묻힙니다.

```markdown
# 우선순위 키워드 활용
- **반드시**: 예외 없이 따라야 하는 규칙
- **가능하면**: 권장 사항
- **절대**: 금지 사항

## 반드시
- PR 생성 전 `npm test` 통과 확인

## 가능하면
- 함수명은 동사로 시작
```

## Tip 4. 예시를 함께 써라

형식을 말로 설명하는 것보다 예시 하나가 훨씬 명확합니다.

```markdown
# 나쁜 예
- 커밋 메시지는 컨벤셔널 커밋 형식으로

# 좋은 예
- 커밋 메시지 형식:
  feat: 새 기능 추가
  fix: 버그 수정
  docs: 문서 변경
  refactor: 리팩토링 (기능 변경 없음)
```

## Tip 5. 200줄을 넘기면 rules/로 분리해라

CLAUDE.md가 길어질수록 지침 준수율이 떨어집니다. 분리 기준:

```
.claude/
├── CLAUDE.md          # 핵심 규칙만 (200줄 이하)
└── rules/
    ├── testing.md     # 테스트 관련 규칙
    ├── git.md         # git 워크플로우
    └── style.md       # 코드 스타일
```

rules/ 파일은 frontmatter로 적용 경로를 지정할 수 있습니다:

```markdown
---
paths:
  - "src/api/**"
---
# API 관련 규칙만 여기에
```

## Tip 6. 개인 선호는 CLAUDE.local.md로 분리해라

팀 공유 규칙과 개인 설정을 섞지 마세요.

```
CLAUDE.md          → git에 포함 (팀 공유)
CLAUDE.local.md    → .gitignore에 추가 (개인 전용)
~/.claude/CLAUDE.md → 모든 프로젝트에 적용되는 개인 전역 설정
```

`CLAUDE.local.md` 예시:
```markdown
- 응답은 항상 한국어로
- 코드 설명은 간결하게, 주석 최소화
```

## Tip 7. @import로 큰 문서를 참조해라

CLAUDE.md에 내용을 직접 쓰는 대신, 기존 파일을 참조하면 토큰을 아낄 수 있습니다.

```markdown
# CLAUDE.md
프로젝트 구조는 @README.md 참조.
API 스펙은 @docs/api.md 참조.
의존성 목록은 @package.json 참조.

## 규칙
- ...
```

Claude가 필요할 때만 해당 파일을 읽으므로 컨텍스트 효율적입니다.

## Tip 8. 맥락(Why)을 함께 써라

이유를 모르면 Claude가 예외 상황에서 판단을 못 합니다.

```markdown
# 나쁜 예
- DB 마이그레이션 전 백업 실행

# 좋은 예
- DB 마이그레이션 전 반드시 백업 실행
  (이유: 롤백 스크립트가 없으므로 실패 시 복구 불가)
```

---

## Tip 9. 검증 가능한 조건으로 써라

Claude가 스스로 "지켰는지"를 확인할 수 있는 형태가 가장 효과적입니다.

```markdown
# 나쁜 예 (검증 불가)
- 코드 품질에 신경 써라

# 좋은 예 (검증 가능)
- `npm run typecheck`가 에러 없이 통과해야 커밋 가능
- 새 함수 추가 시 반드시 테스트 파일도 함께 추가
- PR에는 변경 이유를 한 문장 이상 포함
```

같은 규칙을 여러 번 쓰면 Claude가 어느 것을 따를지 혼란스러워합니다.  
한 번, 한 곳에만 써라.
